# 边缘函数邮件推送服务实现计划

## Context

`scripts/hyde-Supabase-friends.js` 是部署在腾讯云 EdgeOne Pages 的边缘函数，负责友链 CRUD + 审核 + 多平台 IM 推送（钉钉/飞书/Telegram 等）。目前通知只覆盖 IM 渠道，缺少邮件通知能力。

需求：新增邮件推送服务，在友链关键事件触发时自动发邮件给站长，包含模板、收件人配置、状态跟踪与错误处理，与现有 Supabase + 推送体系一致。

**关键约束**：EdgeOne 边缘函数运行在 Serverless 边缘环境，**只能用 `fetch` 发起 HTTP/HTTPS 请求，不支持 SMTP/TCP**（无法直连 25/465/587 端口）。因此邮件必须走 HTTP API 邮件服务，不能引入 nodemailer 之类依赖 SMTP 的库。边缘函数自包含，不能 import 项目 `src/` 下模块。

## 设计方案

复刻现有 `sendPushNotice(title, content)` 多平台推送模式（[scripts/hyde-Supabase-friends.js:129-323](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L129)），新增并行的邮件通道，并提供统一入口 `sendNotice` 同时触发 IM + 邮件，两通道各有独立开关互不阻塞。

- 服务商：默认内置 **Resend** HTTP API 适配，同时支持 **custom** 自定义 endpoint（兼容任意 HTTP 邮件服务），通过 `EMAIL_PUSH_PROVIDER` 环境变量切换。
- 触发事件：新友链申请、后台手动新增、审核通过/拒绝、编辑、删除（全部 5 类）。
- 状态跟踪：`sendEmailNotice` 返回结构化对象 `{sent, provider, status, messageId, error}`，调用处 `console.log/error` 记录；不引入 Supabase 日志表。
- 错误隔离：邮件发送失败不影响友链主流程（不抛出、不让 API 返回 500），与现有 `sendPushNotice` 行为一致。

## 实现步骤

全部改动集中在单文件 [scripts/hyde-Supabase-friends.js](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js)。

### 1. 全局配置区新增邮件配置（在 [L26-40](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L26) `SUPPORT_PUSH_PLATFORMS` 之后）

新增环境变量读取与支持的服务商列表：
- `EMAIL_PUSH_SWITCH`（on/off，默认 off）
- `EMAIL_PUSH_PROVIDER`（resend / custom）
- `EMAIL_PUSH_TO`（收件人，逗号分隔多个）
- `EMAIL_PUSH_FROM`（发件人邮箱）
- `EMAIL_PUSH_FROM_NAME`（发件人名称，默认"友链通知"）
- `EMAIL_API_TOKEN`（服务商 API Token）
- `EMAIL_API_ENDPOINT`（custom 时的完整端点 URL）
- `SUPPORT_EMAIL_PROVIDERS = ["resend", "custom"]`

### 2. 环境变量校验（在 [L48-58](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L48) IM 推送校验之后）

`EMAIL_PUSH_SWITCH === "on"` 时校验：provider 合法、`EMAIL_PUSH_TO`/`EMAIL_PUSH_FROM`/`EMAIL_API_TOKEN` 必填、custom 时 `EMAIL_API_ENDPOINT` 必填。失败抛错，与现有校验风格一致。

### 3. 新增邮件内容模板函数（在 [L323](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L323) `sendPushNotice` 之后，作为新章节 `=== 5.1 邮件内容模板 ===`）

- `renderEmailHtml(title, content)`：把 `\n` 分隔纯文本转 HTML，URL 转可点击链接，套内联样式邮件模板（表格/卡片风格，参考通用邮件最佳实践）。HTML 转义防注入。
- `renderEmailText(title, content)`：纯文本兜底版本。

### 4. 新增邮件发送核心函数（章节 `=== 5.2 邮件发送核心函数 ===`）

`sendEmailNotice(title, content)`，签名与 `sendPushNotice` 对称，返回结构化状态：
- 开关关闭 → `{sent:false, error:"disabled"}`
- 解析收件人列表（逗号分隔）
- 按 provider 构造请求：
  - `resend` → POST `https://api.resend.com/emails`，Header `Authorization: Bearer <token>`，Body `{from, to[], subject, html, text}`
  - `custom` → POST `EMAIL_API_ENDPOINT`，统一 Resend 风格 payload，服务商侧自行适配
- `fetch` 用 try/catch 包裹，失败记录 `console.error` 并返回错误状态，不抛出
- 成功时尝试解析 `messageId`（Resend 返回 `{id}`），返回 `{sent:true, provider, status, messageId}`
- 严格遵循现有 `sendPushNotice` 的错误处理模式（[L275-322](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L275)）

### 5. 新增统一通知入口（章节 `=== 5.3 统一通知入口 ===`）

`sendNotice(title, content)`：用 `Promise.allSettled` 并行调用 `sendPushNotice` 和 `sendEmailNotice`，任一失败不影响另一个，返回 `{push, email}` 汇总状态并记录汇总日志。

### 6. 替换/新增触发点调用

- **替换** [L1351](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L1351) 新友链申请：`sendPushNotice` → `sendNotice`
- **替换** [L1414](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L1414) 后台手动新增：`sendPushNotice` → `sendNotice`
- **新增** [L1376-1387](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L1376) 审核状态变更（PUT `/api/admin/friends`）：原注释"可扩展：审核通过/拒绝推送通知"处，调用 `sendNotice("友链审核状态变更", ...)`，正文含站点名 + 新状态
- **新增** [L1421-1429](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L1421) 编辑（PATCH）：调用 `sendNotice("友链信息已更新", ...)`，正文含站点名 + 更新字段摘要
- **新增** [L1431-1439](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L1431) 删除（DELETE）：调用 `sendNotice("友链已删除", ...)`，正文含被删站点信息

新增触发点的推送均放在 `return json({ success: true })` 之前 `await`，与现有触发点一致。所有触发点统一用 `sendNotice`，IM 与邮件各有独立开关，站长可单独关掉某一通道。

### 7. 后台页面推送状态展示（[L472-478](file:///d:/code/Firefly-hyde/scripts/hyde-Supabase-friends.js#L472) `adminHtml`）

在 `pushStatusText` 旁新增 `emailPushStatusText`，显示邮件推送开关/服务商/收件人，渲染到 `.push-tip` 区域，让管理员一眼看到两通道状态。

## 编码规范

严格对齐现有风格：`const` 配置、`function` 关键字、双引号字符串、2 空格缩进、中文注释、`// === N. 章节 ===` 分节、`console.log/error` 日志、try/catch 错误隔离。不引入任何外部依赖。

## 验证方式

1. **静态检查**：边缘函数无法本地 `pnpm check`（独立运行环境），但需人工通读确认语法、括号配对、章节注释完整。
2. **环境变量配置**（EdgeOne 控制台）：`EMAIL_PUSH_SWITCH=on`、`EMAIL_PUSH_PROVIDER=resend`、`EMAIL_PUSH_TO=you@example.com`、`EMAIL_PUSH_FROM=onboarding@resend.dev`、`EMAIL_API_TOKEN=re_xxx`。
3. **部署验证**：把更新后的 `scripts/hyde-Supabase-friends.js` 粘贴到 EdgeOne 控制台边缘函数并部署。
4. **端到端测试**：
   - 游客提交友链 → 收到邮件 + IM
   - 后台新增/编辑/审核/删除友链 → 各收到对应标题邮件
   - 关闭 `EMAIL_PUSH_SWITCH=off` → 仅 IM，邮件通道返回 `disabled` 不报错
   - 故意填错 `EMAIL_API_TOKEN` → 邮件返回失败状态，但友链 API 仍 `success:true`（错误隔离）
5. **后台页面**：访问 `/api/admin`，确认 `.push-tip` 同时显示 IM 和邮件两通道状态。

## 风险与回滚

- 风险极低：邮件通道默认 `off`，不影响现有线上行为；开启后才生效。
- 邮件失败被 try/catch 隔离，不影响友链 CRUD 主流程。
- 回滚：把新增的邮件相关配置/函数/触发点调用移除即可，或直接将 `EMAIL_PUSH_SWITCH` 设为 `off`。
