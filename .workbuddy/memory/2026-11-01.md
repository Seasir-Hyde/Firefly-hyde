## 一、修复：远程友链「最后更新」始终显示「RSS 暂无」（已提交 3bd65961）

### 根因（本地 vs 远程的数据结构差异）
- 本地友链：`src/config/friendsConfig.ts` → 构建期 `loadFriendsFeed()` 抓 RSS → `rssUpdates` Map（归一化域名 → {date,title,stale}）→ 渲染 `<time class="friend-rss-updated">最近更新于 YYYY-MM-DD</time>`。

  ①接口只返回 `title/desc/siteUrl/imgUrl/tags/weight`，**完全没有时间字段**；
  ②`renderFriendCard()` 里硬编码 `'<span class="friend-rss-updated">RSS 暂无</span>'`。

## 二、分析：远程友链延迟徽章恒为「探测中/待探测」（仅分析，未改码）

### 结论
不是「需要重新探测」，而是**探测数据里根本没有这些站点**。探测队列只含本地友链。

- 探测脚本 `scripts/probe-friends.ts:76` 队列 = `getEnabledFriends()`（本地 38 个），
  远程友链（`/api/friends`）从不入队 → 快照 `results` 只有 38 个键。
- 实测：本地 38/38 命中；远程 24 个仅 1 个命中（`onedayxyy.cn` 因同时是本地友链）→ **23/24 缺失**。
- 客户端 `src/pages/friends.astro:1886-1896` 查表 `latencyResults[key]` 为 undefined → state='checking'、value='待探测'。
- 服务端 `src/utils/friend-latency.ts:19-25` 同样逻辑但文案是「未检测」——两处占位文案不一致。

### 不会导致「待探测」的条件（澄清）
- 探测失败/超时 → 写入 `state:"down"` → 显示「失联」/「HTTP xxx」/「超时」，不是待探测。
- 缓存过期 → UI 完全不校验 `generatedAt`，过期条目照常显示耗时（真实风险是「过期数据被当最新」）。
- 状态未回写 / 异步未完成 → **不存在运行时探测**：浏览器端没有任何对友链站点的 fetch，
  `serviceConfig.friendVisibilityUrl` 为空，`MicrosoftClarity.astro` 只回写点击数（不含 latency）。
  `.friend-latency--checking` 的脉冲动画（friends.astro:2621-2628）只是视觉暗示，没有任务在跑。

### 结构性隐患
- **回写链路跨远端**：GH Actions（`.github/workflows/probe-friends.yml`，每天两次）`git push` 推到 GitHub，
  而站点从 CNB（`origin = cnb.cool`）构建 → 自动探测结果到不了构建源。
- **probeLocation 切换清空整表**：`probe-friends.ts:119` 仅在 probeLocation 相同时才继承 previous.results，
  本地跑一次就丢掉 GH 的全部结果。
- **键口径保留 path**：`normalizeFriendLatencyUrl` 不去 path，同一站点配置与接口 URL 不一致时会查不到。

### 修复方向（按优先级）
1. `probe-friends.ts` 队列改为 `getEnabledFriends()` + `fetchRemoteFriends()` 合并（与 RSS 修复同源）。
2. 归一化改为 hostname 级，或同址多别名键。
3. GH Actions 增加推送 CNB 的步骤（或改由 CNB 定时流水线执行）。
4. 快照改为按键合并 + per-entry probeLocation，避免整表清空。
5. UI：无记录时区分「未纳入探测」并去掉脉冲动画；`getFriendLatencyDisplay` 增加 `checkedAt` 过期阈值。
6. 类型：`FriendLatencyState` 未含 `checking`，但 UI 在用（`friend-latency.ts:22` 返回 `state:"checking"`）。

## 四、重构：探测机制改为 CNB 定时任务 + 部署后状态确认（已实施，待提交）

### 方案变更（对照原方案）
| 项 | 原方案 | 新方案 |
|---|---|---|
| 探测运行位置 | GitHub Actions（`.github/workflows/probe-friends.yml`） | **CNB 定时任务**（`.cnb.yml` 的 `crontab`） |
| 触发频率 | 每天 2 次（UTC 00:17 / 12:17） | **每天 1 次 08:17**（Asia/Shanghai） |
| 结果回写 | 推到 GitHub，与构建源 CNB 断链 | 推到 **CNB main**，直接触发构建，闭环 |
| 凭据 | 需自建 CNB 访问令牌（GitHub Secret） | **CNB 流水线内置临时令牌 CNB_TOKEN**，无需任何 Secret |
| 探测重试 | 无，单次失败即判 down | 单站重试 2 次（指数退避 1.2s/2.4s） |
| 探测限速 | 无（并发 4 直冲） | 相邻请求间隔 ≥150ms |
| 异常保护 | 无（探测器断网会把全站写成失联） | **整轮失败率 >30% 或成功数 <5 → 整轮作废、不写快照、退出码 1** |
| 部署确认 | 无 | 新增 `build-info.json` 构建指纹 + 轮询比对 commit |
| 失败告警 | 无 | CNB `failStages` → 钉钉机器人（构建失败 / 探测失败各一条） |

### 关键经验
- `execSync(\`git ${args}\`)` 中 args 是数组 → JS 会转成逗号分隔，必须 `args.join(" ")`。
- CNB 的 `failStages` 是官方失败告警机制；`crontab` 用 Asia/Shanghai 时区，最小间隔 5 分钟。
- CNB 流水线内置 `CNB_TOKEN`（结束即销毁，可 git push），crontab 触发时以触发者身份签发、限当前仓库。
- 部署后确认不能比对 HTML（边缘缓存 1 天），要用 no-store 的构建指纹文件。
